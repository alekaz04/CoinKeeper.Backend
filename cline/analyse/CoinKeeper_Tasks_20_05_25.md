# План расширения функциональности проекта CoinKeeper

**Дата анализа:** 20.05.2025

## Введение

Данный документ содержит план расширения функциональности проекта CoinKeeper - backend-сервиса для учёта личных финансов, предоставляющего REST API. План основан на анализе текущего состояния проекта и новых требованиях к функциональности.

## Текущее состояние проекта

На данный момент проект находится на ранней стадии разработки с реализованными базовыми компонентами:
- Основная структура проекта (API, Authentication, Finance, Common)
- Сущности User, Operation и Category с базовыми CRUD-операциями
- Начальная миграция базы данных
- Настроенная аутентификация на основе JWT
- Middleware для обработки ошибок
- Документация API через Swagger
- Типизация операций (доход/расход)

## Новые требования к функциональности

На основе анализа требований, необходимо реализовать следующие ключевые фичи:

1. **Добавление бюджета пользователя** - возможность отслеживать конкретный баланс со всех счетов и откладываний
2. **Расчёт будущих поступлений** - возможность внесения будущих поступлений и расчёты будущего баланса
3. **Возможность откладывать деньги** - чтобы они пропадали из секции доступных средств
4. **Внедрение плановых платежей** - возможность создавать регулярные или запланированные платежи

## Оптимальный порядок реализации фич

После анализа зависимостей между фичами, предлагается следующий оптимальный порядок реализации:

1. **Добавление бюджета пользователя** (основа для остальных фич)
2. **Внедрение плановых платежей** (необходимо для расчета будущих поступлений)
3. **Расчёт будущих поступлений** (опирается на плановые платежи)
4. **Возможность откладывать деньги** (дополняет функциональность бюджета)

## Детальный план задач

### Фича 1: Добавление бюджета пользователя

#### Задача 1.1: Создание модели счетов (Account)
- **Описание**: Разработать модель счета пользователя для хранения информации о различных источниках средств

- **Сложность**: Средняя
- **Подзадачи**:
  - Создать сущность Account с полями: Id, Name, Balance, Currency, AccountType, UserId, CreatedAt, UpdatedAt, IsDeleted
  - Создать enum AccountType (Cash, Card, Deposit, Credit, Investment)
  - Реализовать интерфейс IAccount
  - Создать конфигурацию AccountEntityTypeConfiguration
  - Добавить связь с User (один пользователь имеет много счетов)
  - Создать миграцию базы данных

#### Задача 1.2: Реализация API для управления счетами
- **Описание**: Разработать API для создания, чтения, обновления и удаления счетов
- **Приоритет**: Высокий
- **Сложность**: Средняя
- **Подзадачи**:
  - Создать DTO для счетов (AccountCreateDto, AccountReadDto, AccountUpdateDto)
  - Реализовать маппинг между DTO и сущностью Account
  - Создать AccountCrudHandler для бизнес-логики
  - Реализовать AccountController с CRUD-операциями
  - Добавить валидацию для AccountCreateDto и AccountUpdateDto

#### Задача 1.3: Привязка операций к счетам
- **Описание**: Модифицировать модель Operation для связи со счетами
- **Приоритет**: Высокий

- **Подзадачи**:

### API-эндпоинты

Для новых фич потребуется реализация следующих API-эндпоинтов:

1. **Управление счетами**:
   - POST /api/accounts - создание счета
   - GET /api/accounts/{id} - получение счета по ID
   - PUT /api/accounts/{id} - обновление счета
   - DELETE /api/accounts/{id} - удаление счета
   - GET /api/accounts - получение списка счетов пользователя
   - GET /api/accounts/balance - получение общего баланса пользователя

2. **Управление плановыми платежами**:
   - POST /api/planned-operations - создание планового платежа
   - GET /api/planned-operations/{id} - получение планового платежа по ID
   - PUT /api/planned-operations/{id} - обновление планового платежа
   - DELETE /api/planned-operations/{id} - удаление планового платежа
   - GET /api/planned-operations - получение списка плановых платежей пользователя
   - POST /api/planned-operations/{id}/execute - ручное выполнение планового платежа

3. **Прогнозирование баланса**:
   - GET /api/forecast/balance - получение прогноза баланса на указанный период
   - GET /api/forecast/chart-data - получение данных для визуализации прогноза

4. **Управление отложенными средствами**:
   - POST /api/accounts/{id}/save - откладывание средств
   - POST /api/accounts/{id}/withdraw-savings - возврат отложенных средств
   - POST /api/savings-goals - создание цели накопления
   - GET /api/savings-goals/{id} - получение цели накопления по ID
   - PUT /api/savings-goals/{id} - обновление цели накопления
   - DELETE /api/savings-goals/{id} - удаление цели накопления
   - GET /api/savings-goals - получение списка целей накопления пользователя

### Миграции базы данных

Для реализации новых фич потребуется создание следующих миграций:

1. **Миграция для счетов**:
   - Создание таблицы Accounts

2. **Миграция для плановых платежей**:

3. **Миграция для отложенных средств**:

### Фоновые задачи

Для автоматического выполнения плановых платежей потребуется реализация фоновой задачи:

```csharp
public class PlannedOperationsBackgroundService : BackgroundService
{
    private readonly IServiceProvider _serviceProvider;
    private readonly ILogger<PlannedOperationsBackgroundService> _logger;
    private readonly TimeSpan _checkInterval = TimeSpan.FromHours(1);

    public PlannedOperationsBackgroundService(
        IServiceProvider serviceProvider,
        ILogger<PlannedOperationsBackgroundService> logger)
    {
        _serviceProvider = serviceProvider;
        _logger = logger;
    }

    protected override async Task ExecuteAsync(CancellationToken stoppingToken)
    {
        _logger.LogInformation("Planned Operations Background Service is starting.");

        while (!stoppingToken.IsCancellationRequested)
        {
            _logger.LogInformation("Checking for planned operations to execute.");

            try
            {
                using (var scope = _serviceProvider.CreateScope())
                {
                    var executionService = scope.ServiceProvider.GetRequiredService<IPlannedOperationExecutionService>();
                    await executionService.ExecuteDueOperationsAsync(stoppingToken);
                }
            }
            catch (Exception ex)
            {
                _logger.LogError(ex, "Error occurred while executing planned operations.");
            }

            await Task.Delay(_checkInterval, stoppingToken);
        }

        _logger.LogInformation("Planned Operations Background Service is stopping.");
    }
}
```

## Заключение

Предложенный план расширения функциональности позволит значительно улучшить возможности CoinKeeper для управления личными финансами. Оптимальный порядок реализации фич обеспечит последовательное наращивание функциональности с минимальными изменениями в уже реализованном коде. Начиная с базовой функциональности управления счетами, каждая последующая фича будет опираться на предыдущие, расширяя возможности системы.
