# План развития проекта CoinKeeper

## Введение

Данный документ содержит план дальнейшего развития проекта CoinKeeper - backend-сервиса для учёта личных финансов, предоставляющего REST API. План основан на анализе текущего состояния проекта и выявленных проблемах.

## Текущее состояние проекта

На данный момент проект находится на ранней стадии разработки с реализованными базовыми компонентами:
- Основная структура проекта (API, Authentication, Finance, Common)
- Сущности User, Operation и Category с базовыми CRUD-операциями
- Начальная миграция базы данных
- Настроенная (но не полностью реализованная) аутентификация
- Middleware для обработки ошибок
- Базовая документация API через Swagger

**Важное примечание:** Строки подключения к базе данных и настройки JWT в appsettings.json намеренно оставлены пустыми, так как эти чувствительные данные хранятся в переменных окружения (env-файлы Docker) и UserSecrets, что соответствует лучшим практикам безопасности.

## Выявленные проблемы

Основные проблемы, требующие решения:
1. Отсутствие типа операции (доход/расход)
2. Неполная реализация CRUD-операций
3. Несоответствие API-маршрутов REST-конвенциям
4. Ограниченная валидация входных данных
5. Отсутствие пагинации и фильтрации

## План задач

### Задачи первого приоритета

#### Задача 1: Добавление типа операции
- **Описание:** Заменить поле State на enum OperationType
- **Приоритет:** Высокий
- **Сложность:** Средняя
- **Детали:** 
  - Создать enum OperationType (Income/Expense)
  - Обновить модель Operation
  - Обновить DTO и маппинги
  - Создать миграцию базы данных
  - Обновить логику обработки операций с учетом типа

#### Задача 2: Реализация полного CRUD для операций
- **Описание:** Добавить методы обновления и удаления операций
- **Приоритет:** Высокий
- **Сложность:** Средняя
- **Детали:**
  - Реализовать метод Update в OperationsCrudHandler
  - Реализовать метод Delete в OperationsCrudHandler
  - Добавить соответствующие эндпоинты в OperationController
  - Обновить маппинги и DTO при необходимости

#### Задача 3: Реализация полного CRUD для категорий
- **Описание:** Добавить методы обновления и удаления категорий
- **Приоритет:** Высокий
- **Сложность:** Средняя
- **Детали:**
  - Реализовать метод Update в CategoryCrudHandler
  - Реализовать метод Delete в CategoryCrudHandler
  - Добавить соответствующие эндпоинты в CategoryController
  - Обновить маппинги и DTO при необходимости

#### Задача 4: Улучшение валидации
- **Описание:** Расширить правила валидации для всех сущностей
- **Приоритет:** Высокий
- **Сложность:** Средняя
- **Детали:**
  - Добавить правила валидации для Operation:
    - Amount > 0
    - Description не пустой и не более 500 символов
    - Обязательное указание CategoryId
    - Валидация OperationType
  - Добавить правила валидации для Category:
    - CategoryName не пустой и не более 100 символов
    - Уникальность имени категории для пользователя

### Задачи второго приоритета

#### Задача 5: Рефакторинг API-маршрутов
- **Описание:** Привести маршруты в соответствие с REST-конвенциями
- **Приоритет:** Средний
- **Сложность:** Средняя
- **Детали:**
  - Изменить маршруты на стандартные RESTful:
    - POST /api/operations - создание операции
    - GET /api/operations/{id} - получение операции по ID
    - PUT /api/operations/{id} - обновление операции
    - DELETE /api/operations/{id} - удаление операции
    - GET /api/operations - получение списка операций
  - Аналогично обновить маршруты для категорий
  - Обеспечить обратную совместимость или документировать изменения API

#### Задача 6: Реализация фильтрации и пагинации
- **Описание:** Добавить возможность фильтрации и пагинации для списков операций и категорий
- **Приоритет:** Средний
- **Сложность:** Высокая
- **Детали:**
  - Создать DTO для параметров фильтрации:
    - Диапазон дат
    - Тип операции (доход/расход)
    - Категория
    - Диапазон сумм
  - Создать DTO для параметров пагинации:
    - Номер страницы
    - Размер страницы
    - Поле для сортировки
    - Направление сортировки
  - Реализовать соответствующую логику в обработчиках
  - Добавить эндпоинты в контроллеры

#### Задача 7: Расчет баланса за период
- **Описание:** Реализовать эндпоинт для получения баланса за выбранный период
- **Приоритет:** Средний
- **Сложность:** Средняя
- **Детали:**
  - Создать DTO для параметров периода (начальная и конечная дата)
  - Создать DTO для результата (доходы, расходы, баланс)
  - Реализовать логику расчета баланса за период
  - Добавить эндпоинт в контроллер

### Задачи третьего приоритета

- **Сложность:** Средняя
- **Детали:**

  - Реализовать логику выборки и сортировки категорий по сумме операций
  - Добавить эндпоинт в контроллер

#### Задача 10: Улучшение документации API

- **Приоритет:** Низкий
- **Сложность:** Низкая

Реализация этих задач приведет к созданию полноценного API для управления личными финансами, соответствующего современным стандартам разработки.
