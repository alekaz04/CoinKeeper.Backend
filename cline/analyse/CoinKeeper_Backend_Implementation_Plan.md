# CoinKeeper Backend - План реализации для Frontend готовности

**Дата создания:** 24.07.2025  
**Цель:** Детальный план задач для подготовки backend к разработке frontend

---

## СЕКЦИЯ 1: Критически необходимые задачи (1-2 дня)

### Блок 1.1: Исправление валидации операций
**Проблема:** В OperationValidator отсутствует валидация AccountId  
**Что нужно сделать:**
- Добавить правило валидации для поля AccountId в OperationValidator
- Проверить, что AccountId не пустой
- Добавить проверку существования счета в базе данных
- Убедиться, что счет принадлежит текущему пользователю
- Добавить соответствующие сообщения об ошибках на русском языке

**Результат:** Операции не смогут быть созданы без корректного счета

### Блок 1.2: Улучшение обработки часовых поясов
**Проблема:** PlannedOperationsJob использует DateTimeOffset.Now без учета часового пояса пользователя  
**Что нужно сделать:**
- Добавить поле TimeZone в модель User (строка, например "Europe/Moscow")
- Обновить миграцию для добавления поля TimeZone
- Изменить логику в PlannedOperationsJob для использования часового пояса пользователя
- Обеспечить консистентность работы с датами во всех API эндпоинтах
- Все даты в API должны возвращаться в UTC, а клиент будет конвертировать в локальное время

**Результат:** Плановые операции будут выполняться в правильное время для каждого пользователя

### Блок 1.3: Добавление транзакций в фоновые задачи
**Проблема:** PlannedOperationsJob не использует транзакции  
**Что нужно сделать:**
- Обернуть каждое выполнение плановой операции в отдельную транзакцию
- При ошибке выполнения операции откатывать все изменения
- Добавить логирование успешных и неудачных транзакций
- Обеспечить атомарность операций изменения баланса

**Результат:** Гарантия целостности данных при выполнении плановых операций

## СЕКЦИЯ 2: Базовая функциональность (2-3 дня)

### Блок 2.1: Реализация фильтрации и пагинации

#### 2.1.1: Создание базовых DTO для пагинации
**Что нужно создать:**
- `PaginationRequest` - базовый класс для запросов с пагинацией
- `PaginationResponse` - информация о пагинации в ответе
- `PagedResult<T>` - обертка для списочных данных с пагинацией
- `SortingRequest` - параметры сортировки

#### 2.1.2: Фильтрация операций
**Что нужно создать:**
- `OperationFilterDto` с полями:
  - DateFrom, DateTo (фильтр по дате)
  - CategoryId (фильтр по категории)
  - AccountId (фильтр по счету)
  - OperationType (Income/Expense)
  - AmountFrom, AmountTo (фильтр по сумме)
  - Search (поиск по описанию)

#### 2.1.3: Обновление контроллеров и хендлеров
**Что нужно изменить:**
- Обновить OperationController для поддержки фильтрации
- Изменить OperationsCrudHandler для работы с фильтрами
- Добавить пагинацию в CategoryController
- Добавить пагинацию в AccountController
- Добавить пагинацию в PlannedOperationController

**Результат:** Все списочные эндпоинты поддерживают фильтрацию, сортировку и пагинацию

### Блок 2.2: Расширение типов счетов
**Что нужно сделать:**
- Расширить enum AccountType, добавив:
  - Deposit (Депозит)
  - Credit (Кредитный счет)
  - Investment (Инвестиционный счет)
  - Savings (Сберегательный счет)
  - Cryptocurrency (Криптовалютный кошелек)
- Обновить валидацию AccountValidator
- Обновить маппинги AccountMapper
- Создать миграцию для обновления существующих данных
- Обновить Swagger документацию

**Результат:** Пользователи смогут создавать счета разных типов

### Блок 2.3: Добавление поддержки валют
**Что нужно создать:**
- Enum Currency с основными валютами:
  - RUB (Российский рубль)
  - USD (Доллар США)
  - EUR (Евро)
  - GBP (Британский фунт)
  - CNY (Китайский юань)

**Что нужно изменить:**
- Добавить поле Currency в модель Account
- Добавить поле Currency в модель Operation (для отображения)
- Обновить DTO: AccountCreateDto, AccountReadDto, OperationReadDto
- Обновить валидацию и маппинги
- Создать миграцию для добавления поля Currency
- Установить RUB как валюту по умолчанию

**Результат:** Каждый счет имеет свою валюту, операции отображают валюту счета
